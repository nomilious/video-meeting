# 03: Удаление файла встречи

**What to build:** Владелец удаляет выбранный файл, видит обновлённый список и может загрузить новый файл на освободившееся место.

**Blocked by:** 01 — Загрузка и отображение файлов встречи.

**Status:** ready-for-agent

- [ ] У каждого файла есть явное действие удаления; удаляется только выбранный файл. На время запроса повторная отправка блокируется.
- [ ] После успеха файл исчезает из списка и больше не доступен через API. После удаления последнего файла отображается пустое состояние; лимит позволяет загрузить новый файл.
- [ ] Сервер проверяет авторизацию, владельца и принадлежность файла встрече; чужой или отсутствующий ресурс не раскрывается. Другие файлы и сведения встречи сохраняются.
- [ ] Ошибка удаления явно показывается пользователю. После сетевого сбоя с неопределённым результатом перечитывается список; UI не объявляет успех без подтверждения фактического состояния.
- [ ] Определено согласованное поведение при конкурирующих удалении и загрузке, сбое БД и сбое удаления объекта. Файл не исчезает безвозвратно при откате; недоступные остаточные объекты подлежат безопасной очистке.
- [ ] Документирована процедура сверки хранилища с БД и очистки сирот после аварии; она не удаляет связанные или находящиеся в процессе сохранения файлы.
- [ ] Реальный пользовательский сценарий проверяет удаление, обновление страницы и новую загрузку после освобождения места. API-проверки покрывают изоляцию, конкуренцию и сбои; браузерные — доступность и сообщения состояния.
- [ ] Контракт удаления и генерируемые типы обновлены; проходят затронутые проверки типов и lint. Документированы удаление и восстановление после сбоев.
