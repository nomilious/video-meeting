# 01: Загрузка и отображение файлов встречи

**What to build:** Владелец открывает детали встречи из списка, выбирает файл, явно запускает загрузку и видит сохранённые файлы после обновления страницы. Согласованный объём: до 3 файлов на встречу, включая TXT/MD; замена и удаление реализуются отдельными задачами.

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] Детали встречи показывают название, дату, участников и список файлов либо понятное пустое состояние. Существующее создание и чтение встреч сохраняют поведение.
- [ ] Перед отправкой видны имя и размер выбранного файла; выбор можно изменить. Допустимые форматы и действующий лимит приходят от API. TXT и MD включены наряду с форматами записи из спецификации; 500 MiB остаётся предложенным настраиваемым значением.
- [ ] Сервер проверяет фактический размер при потоковом чтении и допустимость содержимого; пустые и неподдерживаемые файлы отклоняются. Проверка не доверяет только MIME браузера.
- [ ] БД хранит метаданные и связь со встречей, постоянный volume — оригинал. Миграция сохраняет существующие встречи. Сервер генерирует ключ хранения; пользовательское имя не используется как путь и внутренний путь не возвращается клиенту.
- [ ] Успешное сохранение возвращает идентификатор, исходное имя, размер, тип и время загрузки. UI показывает «Файл сохранён» без фиктивного состояния обработки.
- [ ] Не более 3 файлов могут быть сохранены одновременно, включая конкурентные загрузки; превышение возвращает конфликт. Модель допускает отдельное обращение к каждому файлу.
- [ ] Авторизация и владение проверяются сервером. Чужая или отсутствующая встреча даёт 404, отсутствие авторизации — 401; превышение размера — 413, неподдерживаемый тип — 415, некорректный или пустой файл — 422. Файлы не доступны через публичную статику.
- [ ] UI показывает загрузку и понятные ошибки, блокирует повторное нажатие и обрабатывает истечение сессии. После неопределённого результата перечитывает список, прежде чем разрешить повтор, исключающий дубликат уже сохранённого файла.
- [ ] При уходе со страницы отменяется клиентский запрос; это не считается гарантированной отменой серверного сохранения. Временные объекты очищаются при штатных сбоях, неполный файл не отображается как сохранённый.
- [ ] Сквозная проверка с реальным API подтверждает загрузку и отображение после обновления страницы. API-проверки покрывают доступ, валидацию, лимит и конкуренцию; браузерные — состояния, мобильный экран и управление клавиатурой.
- [ ] Общий API-клиент и генерируемые OpenAPI-типы обновлены; проходят затронутые проверки типов и lint. Документированы API, модель хранения, настройки лимита и постоянный volume.

## Scope decision

При согласовании разбиения пользователь подтвердил до 3 файлов и поддержку замены и удаления. Это разрешает противоречия исходной спецификации; её исключение этих операций не применяется к согласованным задачам. Реализация обработки, проигрывателя и версий файлов остаётся вне объёма.
